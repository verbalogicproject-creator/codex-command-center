Capability library implemented

A persistent, versioned library of provider-neutral instructions — not executable packages, never dynamically installed into a coding client. Only the exact selected version enters a handoff.

Trust filtering

Only verified or workspace-trusted latest versions are recommended for new handoffs; an existing handoff keeps the exact version it pinned.

  • verified — built-in or administrator-reviewed import
  • workspace — authored in the current trusted workspace
  • untrusted — stored but omitted from normal selection
  • retired — preserved for old handoffs, not chosen for new

Identity & integrity

Composite key (stable_id, version). Re-authoring the same stable_id mints the next integer version. The server computes a canonical SHA‑256 content hash and records creation and verification times. Instructions are provider-neutral and contain no arbitrary executable payload.

Handoff lifecycle implemented

A handoff is a reusable, inspectable task artifact — separate from durable memory, containing no arbitrary executable code.

draft ──publish──▶ published ──revoke──▶ revoked │ │ └── edit in place └── edit request ──▶ new draft version

Draft

Compiles repository identity, original intent, screenshot metadata & findings, exact capability versions, an Open Plan, declared architecture, ranked evidence receipts, safe edit points, risks, tool references, token estimate, omitted-candidate count, and degraded-state metadata. The packet preview is the data Codex will receive.

Publication

Requires the explicit browser action or voice phrase “Approve this handoff.” Published records are immutable — a direct patch returns HTTP 409. Editing through the versions endpoint creates a new draft with the same lineage; previous versions stay inspectable.

Activation

load_handoff fails unless the handoff is published and the repository matches case-insensitively. Every successful load records a distinct activation ID, client name, optional session ID, repository, evidence IDs, and timestamp. The packet carries interview_required=true.

Revocation

Prevents new loads while keeping activation receipts and the record for audit. It does not delete memories, capabilities, repository documents, or prior client session data. The handoff ID is not a bearer secret — the paired token and repository verification still apply.

Screenshot discipline implemented

Screenshot bytes exist only long enough to be useful, then vanish. Every returned observation is labelled an inference.

1

Validate & MIME-sniff

PNG / JPEG / WebP only; unsupported or corrupt bytes return 422.

2

Bound & resize

Enforce size and dimension limits; resize the analysis copy in memory.

3

Hash

Compute a SHA‑256 receipt of the original.

4

Optional Sol

Call GPT‑5.6 Sol via Responses only when an API key is configured.

5

Discard

Stored record = hash, dimensions, MIME, findings. Raw bytes never retained.

The current implementation always reports retained=false, even if a caller requests retention. Returned observations always carry classification=inference. Without an API key, screenshots are still validated, hashed, and discarded; findings fall back to visibly degraded local results.

Context & retrieval implemented

A bounded context compiler rank-fuses declared documents and durable memory, then enforces a token and entity-count bound. Its POST response is the common agent interface — prompts never enter URLs or access-log query strings.

Signals fused

  • Declared — copied from validated AI-cards
  • Lexical + structural — deterministic, always available
  • Dense — normalized float32 vector cache
  • Durable memory — human-authored/confirmed facts & episodes

Each source shows its stable ID, entity class, repository, and selection reasons. The packet header shows used / budget estimated tokens — a conservative bound, not a tokenizer bill.

Embedding surface

The canonical surface contains only entity type, project, kind, status, tags, title, content, and reason — no identifiers, secrets, or arbitrary metadata. SHA‑256 hashes select changed rows.

  • Local deterministic — hash provider + pure-Python cosine; fully offline
  • OpenAI — text-embedding-3-large, dimensions=256, batches of 64
If dense embeddings or OpenAI are unavailable, writes still persist and retrieval returns lexical/structural/declared evidence marked degraded=true — with a human-readable reason and counted omissions rather than silent gaps.

Aria voice implemented

Voice is an optional control layer over the same typed command router that tests and visible buttons use — not a second agent or memory service. The declared command catalog does not import a voice SDK.

Transport

The authenticated user submits a BYOK credential once over HTTPS. The backend seals it into an HttpOnly session envelope and mints a ten-minute ephemeral OpenAI Realtime client secret; the original key is never returned to or readable by browser JavaScript. With no credential, voice returns provider_credential_required. The browser opens a WebRTC peer connection directly to OpenAI using only the ephemeral secret. A privacy-preserving hash of the workspace ID is sent as the safety identifier. Defaults: gpt-realtime-2.1, voice marin.

Closing voice stops local media tracks, the data channel, remote audio, and the peer connection together.

What voice may & may not do

  • ✅ Navigate seven surfaces, scroll, open evidence, run recall, focus the graph, drive the guided tour
  • ✅ Draft a pending proposal · publish a bounded handoff after the exact phrase

  • 🚫 Cannot edit code, install, deploy, or take external action

Architecture awareness implemented

The complete declared architecture is versioned and queryable, while each model receives only the relevant repository-scoped slice. One ArchitectureBrief is shared by Aria, handoffs, MCP, and Codex hooks. Codex Command Center v0.5 adds migration 6 planning receipts, deterministic redesign suggestions, controller-backed voice drafting, and an evidence-aware Luna tour.

Sync the architecture once. Plan with Aria. Continue in Codex with the same repository understanding and evidence receipts.

How it works

  • Manifest-driven — .command-center/architecture.yaml is the only discovery authority (id, aliases, Markdown roots, dialects); it holds no token, path, or document body.
  • Two dialects → one card — root YAML frontmatter (Declarum) and fenced ai_card YAML (Atlas) normalize to one strict provider-neutral ArchitectureCard (13 fleet slots). If a file has both, they must be identical.
  • Explicit sync — lint validates, status sends hashes only, sync shows the corpus and asks before upload. SessionStart runs status, never sync.
  • Immutable snapshots — each sync stages, then activates transactionally; the prior snapshot becomes historical; a pinned handoff stays byte-resolvable forever.
  • Declaration over inference — typed edges come only from declarations; unresolved targets remain visible issues, never invented edges.

The shipped surface

Migration 5 adds seven tables: architecture_repositories · _snapshots · _document_versions · _sections · _section_embeddings · _edges · _issues.

  • POST /architecture/lint · /sync · /check · /brief
  • GET /architecture/health — coverage, drift, conflicts, degraded reasons
  • Brief modes: boot (orientation) + task (request-ranked)
  • Evidence IDs: adoc_ · asec_ · aedge_ · aissue_
  • Typed edges: CONTAINS PART_OF DESCRIBES OWNS_CONTRACT PROVIDES DEPENDS_ON SAFE_EDIT_POINT RISK_AREA MENTIONS
Proven lineage — the contract consolidates three working systems: Atlas / kg-factory (fenced ai_card, Markdown-AST H2 chunking, PostgreSQL graph, visible gap nodes), NLKE Declarum Game Engine (the 13 declaration slots, lint/scaffold/staleness, minimal boot context), and Command Center (repository-aware retrieval, bounded compilation, immutable handoffs, MCP parity, Codex hooks). The four durable operations

Only the authenticated confirm endpoint executes one of: remember_episode, record_fact, supersede_fact, invalidate_fact. Confirmation is idempotent; rejection changes no memory. The MUD guard transitions a proposal to failed when it conflicts with an active project-boundary decision — without changing memory.

Pairing & tokens

A signed HttpOnly, SameSite=Lax cookie authenticates the browser. Pair Codex creates a one-time code (5-minute expiry, stored hashed) exchanged once for a revocable workspace token. The server stores only SHA‑256 hashes; the plugin keeps the original outside the repository with user-only permissions. Direct clients send it via X-Command-Center-Token.

Bring your own key implemented

The public deployment is BYOK: no operator OpenAI key funds public Aria, Sol, or Realtime. Hosted retrieval defaults to deterministic hash embeddings; an optional administrative embedding credential may index architecture in a controlled environment but cannot fund interactive model routes. An authenticated user posts their key over HTTPS; the backend seals it into an authenticated, expiring Fernet envelope (credentials.py) returned only as an HttpOnly, Secure, SameSite cookie (cc3_openai_byok) scoped to /api/v1 and bound to one workspace. Browser JS can't read it; the plaintext never reaches PostgreSQL, SQLite, handoffs, memory, snapshots, MCP packets, or logs, and it decrypts only for that user's outbound request.

Stack & deployment implementation-ready

The proven baseline is one combined image (static web + REST API + stateless MCP). The production target — implemented in source and staged for promotion — splits it into three independently deployable Cloud Run services built from one commit by cloudbuild.three-service.yaml, keeping the rollback path to the combined revision. Google Cloud is only the hosting layer — Command Center exposes no GCP administration tools.

command-center-web

Static Next.js export + a same-origin reverse proxy to the API, preserving the HttpOnly/Secure/SameSite=Lax cookie contract. Owns no database, token, key, or durable state.

command-center-api

FastAPI: auth, pairing, capabilities, screenshots, handoffs, architecture sync, context, Aria, memory, audit. declared_core + vendored frontmatter_rag · SQLite (local) / Cloud SQL PostgreSQL (prod, migration 5 verified under proot).

command-center-mcp

Stateless Streamable HTTP MCP boundary only (mcp_app.py) + a minimal /healthz. Imports the same canonical tool schemas; scale-to-zero safe. The stdio plugin forwards tools/call here.

Least-privilege identity

The production target creates separate runtime service accounts for web, API, and MCP. Web has no Secret Manager or Cloud SQL access by default; API receives Cloud SQL Client plus only its named cookie, signing, and BYOK-envelope secrets; MCP receives Cloud SQL Client plus only the signing secrets required by canonical handlers. No Editor, Owner, deploy, build, or general storage roles. The planned secret inventory includes DEMO_ACCESS_CODE, COOKIE_SECRET, the BYOK envelope secret, MCP signing, and DATABASE_URL — never an operator OPENAI_API_KEY. These identities and secrets do not exist yet.

Structured logging

Logs carry route, status, latency, workspace hash prefix, MCP method, degraded state, and error code — never headers, bodies, prompts, tokens, or screenshots. Planned alerts cover 5xx/latency, MCP failures, Cloud SQL exhaustion, repeated provider-auth failures, and the bounded monthly GCP budget threshold.

Legend of receipts

Two vocabularies run through the whole product. Evidence class answers “how do we know this?” Graph color answers “what kind of thing is lit?”

Evidence class

  • declared — copied from a validated architecture card
  • derived — produced deterministically from structure or path normalization
  • inferred — produced by a model or heuristic (e.g. screenshot findings)
  • verified — checked against source content at a recorded hash or revision

Inferred relationships never silently become declared graph edges.

Graph palette (in-product)

  • Violet — declared repository, document & stored capability structure
  • Amber — human-authored or human-confirmed durable memory
  • Cyan + moving particle — Sol-selected context or an active handoff entering Codex
  • Muted edge — a relationship that exists but is inactive for this question
  • Dimmed card — superseded evidence retained for provenance

With reduced motion, state stays legible through color, labels, icons, and borders.
